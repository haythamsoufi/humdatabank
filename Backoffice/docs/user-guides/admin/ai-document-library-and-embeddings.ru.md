# Библиотека и встраивания документов на базе искусственного интеллекта

В этом документе описывается, как работает AI Document Library: как обрабатываются документы, как генерируются эмбеддинги (векторы) и как они используются для семантического поиска и RAG (Retrieval-Augmented Generation).

## Обзор

AI Document Library позволяет администраторам загружать документы (PDF, Word и др.), чтобы чат-бот и инструменты ИИ могли отвечать на вопросы, используя этот контент. Документы:

1. **Extracted** — из файла извлекаются текст, страницы, разделы и, по необходимости, таблицы.
2. **Chunked** — разбить на меньшие текстовые блоки для ограничения контекста и токенов.
3. **Embedded** — каждый кусок превращается в вектор (embedding) с помощью модели вложения.
4. **Хранится** — векторы хранятся в базе данных (pgvector) и связываются с чанками.

Когда пользователь задаёт вопрос, запрос встраивается в ту же модель, и система находит наиболее похожие части (векторный или гибридный поиск) и использует их как контекст для ответа.

## Конвейер обработки документов

Обработка запускается, когда вы:

- **Загрузить** документ на странице AI Document Library (`/admin/ai/documents`).
- **Выбранные документы обработки** импортируются из системы управления документами.
- **Переобработка** существующий документ (повторное извлечение, перефрагментирование, повторное встраивание).

Шаги конвейера (см. `app/routes/ai_documents.py`, `_process_document_sync`):

| Шаг | Что происходит |
|------|----------------|
| **1. Выписка** | `AIDocumentProcessor` читает файл и извлекает текст, границы страниц, разделы и (по необходимости) таблицы. |
| **2. Чанк** | `AIChunkingService` разбивает текст на части (по умолчанию: семантическое блокирование, ~512 токенов на блок, перекрытие на 50 токенов). Необязательно: таблицные блоки и визуальные части UPR. |
| **3. Генерировать вложения** | Только если документ отмечен как *поисковый*. `AIEmbeddingService` превращает текст каждого фрагмента в вектор (см. [Embedding providers](#embedding-providers) ниже). |
| **4. Магазин** | `AIVectorStore` сохраняет каждый вектор в таблице `AIEmbedding` (pgvector), связанной с соответствующим `AIDocumentChunk`. |

Записи чанка (`AIDocumentChunk`) всегда создаются; Эмбеддинги создаются только тогда, когда документ доступен для поиска.

## Встраивающие провайдеры

Вложения генерируются с помощью `app/services/ai_embedding_service.py`. Поддерживаются два провайдера.

### OpenAI (по умолчанию)

- **Провайдер:** `AI_EMBEDDING_PROVIDER=openai` (по умолчанию).
- **Model:** `AI_EMBEDDING_MODEL` — по умолчанию `text-embedding-3-small`.
- **Dimensions:** `AI_EMBEDDING_DIMENSIONS` — по умолчанию `1536` (должно совпадать с столбцем pgvector).
- **Где он работает:** На **серверах OpenAI**. Ваше приложение отправляет фрагменты текста в API OpenAI и получает векторы. Вам нужен набор `OPENAI_API_KEY`.
- **Стоимость:** Оплачивается за токен OpenAI (например, text-embedding-3-small — это низкая стоимость за 1M токенов).

То есть **`text-embedding-3-small` не запускается локально** — он используется через API OpenAI.

### Локальный (Трансформеры предложений)

- **Провайдер:** `AI_EMBEDDING_PROVIDER=local`.
- **Модель:** `all-MiniLM-L6-v2` (фиксировано в сервисе) — 384 измерения.
- **Где он работает:** **На твоём аппарате**. Приложение загружает модель с библиотекой `sentence_transformers`; внешний API не вызывается.
- **Стоимость:** Без стоимости за жетон; требуется `pip install sentence-transformers` и достаточное количество оперативной памяти/процессора.

Если вы используете локальные эмбеддинги, вы должны:

- Установить `AI_EMBEDDING_DIMENSIONS=384`.
- Убедитесь, что столбец pgvector базы данных имеет 384 измерения (может потребоваться миграция). Схема по умолчанию — 1536 для OpenAI.

## Конфигурационная ссылка

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `AI_EMBEDDING_PROVIDER` | `openai` | `openai` или `local`. |
| `AI_EMBEDDING_MODEL` | `text-embedding-3-small` | Название модели (только для OpenAI; игнорируется для `local`). |
| `AI_EMBEDDING_DIMENSIONS` | `1536` | Размер вектора. Должно совпадать с столбцем DB и моделью (1536 для text-embedding-3-small, 384 для all-MiniLM-L6-v2). |
| `OPENAI_API_KEY` | — | Требуется при `AI_EMBEDDING_PROVIDER=openai`. |
| `AI_CHUNK_SIZE` | `512` | Целенаправленный размер чанка в токенах. |
| `AI_CHUNK_OVERLAP` | `50` | Перекрытие между последовательными чанками (токенами). |
| `AI_MAX_DOCUMENT_SIZE_MB` | `50` | Максимальный размер файла для обработки. |
| `AI_TOP_K_RESULTS` | `5` | Количество кусков, возвращенных для поиска. |

См. `Backoffice/config/config.py` для полного раздела ИИ/RAG и любых дополнительных опций.

## Как используются векторы

- **Векторный поиск:** Пользовательский запрос встроен в тот же сервис вложения; Приложение запускает поиск по сходству (например, косинус) в pgvector и возвращает верхние k блоки.
- **Гибридный поиск:** Объединяет векторное сходство и поиск по ключевым словам для лучшего запоминания.
- **RAG:** Полученные части передаются в качестве контекста LLM при ответах на вопросы (чат-бот, вопросы и ответы по AI Document Library, документация по рабочему процессу).

Страница AI Document Library позволяет выбрать **Только вектор** или **Гибрид (ключевые слова и вложения)** для функции «Спросить».
