# Добавить нового пользователя

Используйте это руководство, чтобы создать новый аккаунт Backoffice и назначить соответствующие роли.

## Прежде чем начнёшь

- Вам нужен доступ **Admin** с правами на создание пользователя.
- Понять систему **RBAC (Role-Based Access Control)** — пользователи могут иметь несколько ролей.
- Для пользователей, которые будут работать с заданиями, знайте, к какому **стране/стране** или **организациям** им следует обращаться.

## Шаги

1. Открыть **Панель администраторов** → **Управление пользователями** → **Управление пользователями**.
2. Нажмите **Добавить нового пользователя**.
3. Заполните необходимые поля во вкладке **User Details**:
   - **Email**: это будет имя пользователя для входа
   - **Полное имя**
   - **Название** (по желанию): должность
   - **Начальный пароль** (следуйте политике пароля вашей организации)
4. Выберите **тип роли**:
   - **Admin**: для пользователей, которым нужен административный доступ
   - **Focal Point**: для пользователей, которые будут вводить и отправлять данные заданий
5. Назначьте **Роли** в зависимости от типа роли:
   - **Для администраторов**: выбирайте из ролей администратора (например, Админ: полная, Админ: Основная, или конкретные роли менеджера, такие как Админ: Менеджер шаблонов)
   - **Для фокусных точек**: Выберите роли назначения (обычно `Assignment Editor & Submitter` для ввода данных)
   - Пользователи могут иметь несколько ролей — см. [User Roles and Permissions](user-roles.md) для подробностей
6. Перейдите на вкладку **Permissions of Entity**:
   - Назначить **хотя бы одну страну** (или организацию) для контактных точек — им это нужно для просмотра назначений
   - Администраторам также могут понадобиться назначения по странам в зависимости от их ролей
7. Нажмите **Создать пользователя**.

## После создания пользователя ##

- Передайте данные для входа с пользователем **securely**.
- Если пользователь не видит ожидаемые данные, проверьте его **роли** и **назначения** (страны/организации).

## Советы

- **Начните с пресетов**: Используйте пресеты «Admin: Core» или «Admin: Full» для администраторов, затем добавляйте конкретные роли по необходимости.
- **Контактные точки нуждаются в странах**: Пользователи с назначенными ролями должны быть назначены в определённые страны/организации для просмотра назначения.
- **Несколько ролей**: При необходимости пользователи могут выполнять как административную, так и назначочную.
- См. [User Roles and Permissions](user-roles.md) для подробного описания ролей.

## Общие проблемы

- **Пользователь может войти, но не видит назначений**: скорее всего, у него нет назначенной страны или организации. Назначьте хотя бы одну сущность во вкладке Permissions Entity.
- **Доступ к страницам администратора запрещён**: подтвердите, что назначены соответствующие роли администратора (проверьте раздел «Роли»).
- **Пользователь не может назначать роли другим**: только пользователи с разрешением `admin.users.roles.assign` могут назначать роли.
