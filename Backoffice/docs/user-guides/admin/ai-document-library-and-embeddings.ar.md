# مكتبة مستندات الذكاء الاصطناعي والتضمينات

تصف هذه الوثيقة كيفية عمل مكتبة مستندات الذكاء الاصطناعي: كيف تتم معالجة المستندات، وكيفية توليد التضمين (المتجهات)، وكيفية استخدامها للبحث الدلالي وتوليد الاسترجاع المعزز (RAG).

## نظرة عامة

تتيح مكتبة مستندات الذكاء الاصطناعي للمديرين رفع المستندات (PDF، وورد، إلخ) حتى يتمكن روبوت الدردشة وأدوات الذكاء الاصطناعي من الإجابة على الأسئلة باستخدام هذا المحتوى. الوثائق هي:

1. **تم استخراجه** — يتم استخراج النصوص، والصفحات، والأقسام، والجداول الاختيارية من الملف.
2. **مجزأ** — مقسم إلى أجزاء نصية أصغر لتحديد السياق وحدود الرموز.
3. **مدمج** — يتم تحويل كل جزء إلى متجه (تضمين) بواسطة نموذج تضمين.
4. **مخزن** — يتم تخزين المتجهات في قاعدة البيانات (pgvector) وترتبط بالأجزاء.

عندما يطرح المستخدم سؤالا، يتم تضمين الاستعلام مع نفس النموذج، ويجد النظام الأجزاء الأكثر تشابها (بحث متجه أو هجين) ويستخدمها كسياق للإجابة.

## خط معالجة المستندات

المعالجة تعمل عندما:

- **رفع** وثيقة على صفحة مكتبة مستندات الذكاء الاصطناعي (`/admin/ai/documents`).
- **معالجة المستندات المختارة** المستوردة من نظام إدارة المستندات.
- **إعادة معالجة** مستند موجود (إعادة استخراج، إعادة تقسيم، إعادة تضمين).

خطوات خط الأنابيب (انظر `app/routes/ai_documents.py`, `_process_document_sync`):

| الخطوة | ماذا يحدث |
|------|----------------|
| **1. مقتطف** | `AIDocumentProcessor` يقرأ الملف ويستخرج النصوص، وحدود الصفحات، والأقسام، و(اختياريا) الجداول. |
| **2. تشانك** | `AIChunkingService` يقسم النص إلى أجزاء (افتراضي: تقسيم دلالي، ~512 رمزا لكل قطعة، تداخل 50 رمزا). اختياري: قطع الطاولة وأجزاء بصرية من UPR. |
| **3. توليد التضمينات** | فقط إذا كان المستند معلما ب *قابل للبحث*. `AIEmbeddingService` يحول نص كل جزء إلى متجه (انظر [Embedding providers](#embedding-providers) أدناه). |
| **4. المتجر** | `AIVectorStore` يحفظ كل متجه في جدول `AIEmbedding` (pgvector)، مرتبط ب `AIDocumentChunk` المقابل. |

يتم دائما إنشاء سجلات القطع (`AIDocumentChunk`); يتم إنشاء التضمينات فقط عندما يكون المستند قابلا للبحث.

## مزودو التضمين

يتم توليد التضمينات بواسطة `app/services/ai_embedding_service.py`. يتم دعم مزودين فقط.

### OpenAI (default)

- **المزود:** `AI_EMBEDDING_PROVIDER=openai` (الافتراضي).
- **نموذج:** `AI_EMBEDDING_MODEL` — الافتراضي `text-embedding-3-small`.
- **الأبعاد:** `AI_EMBEDDING_DIMENSIONS` — الافتراضي `1536` (يجب أن يطابق عمود pgvector).
- **حيث يعمل:** على **خوادم OpenAI**. تطبيقك يرسل نصا جزئيا إلى واجهة برمجة تطبيقات OpenAI ويتلقى متجهات. تحتاج إلى مجموعة `OPENAI_API_KEY`.
- **التكلفة:** يتم احتساب كل رمز من OpenAI (مثلا: تضمين نصي-3-صغير هو تكلفة منخفضة لكل مليون رمز).

لذا **`text-embedding-3-small` لا يتم تشغيله محليا** — بل يستخدم عبر واجهة OpenAI.

### محلي (محولات الجمل)

- **المزود:** `AI_EMBEDDING_PROVIDER=local`.
- **نموذج:** `all-MiniLM-L6-v2` (ثابت في الخدمة) — 384 بعدا.
- **حيث يعمل:** **على جهازك**. يقوم التطبيق بتحميل النموذج بمكتبة `sentence_transformers`؛ لا يتم استدعاء واجهة برمجة تطبيقات خارجية.
- **التكلفة:** لا توجد تكلفة لكل رمز؛ يتطلب `pip install sentence-transformers` وذاكرة RAM ومعالج كافية.

إذا كنت تستخدم التضمينات المحلية، يجب عليك:

- اضبط `AI_EMBEDDING_DIMENSIONS=384`.
- تأكد من أن عمود pgvector في قاعدة البيانات يكون 384 بعدا (قد يكون مطلوبا الترحيل). المخطط الافتراضي هو 1536 ل OpenAI.

## مرجع التكوين

| متغير | الافتراضي | الوصف |
|----------|---------|-------------|
| `AI_EMBEDDING_PROVIDER` | `openai` | `openai` أو `local`. |
| `AI_EMBEDDING_MODEL` | `text-embedding-3-small` | اسم النموذج (OpenAI فقط؛ تم تجاهله ل `local`). |
| `AI_EMBEDDING_DIMENSIONS` | `1536` | حجم الناقل. يجب أن يطابق عمود قاعدة البيانات والنموذج (1536 لتضمين النص 3 صغير، 384 للجميع MiniLM وL6 v2). |
| `OPENAI_API_KEY` | — | مطلوب عندما `AI_EMBEDDING_PROVIDER=openai`. |
| `AI_CHUNK_SIZE` | `512` | حجم القطعة المستهدف بالرموز. |
| `AI_CHUNK_OVERLAP` | `50` | التداخل بين القطع المتتالية (الرموز). |
| `AI_MAX_DOCUMENT_SIZE_MB` | `50` | الحد الأقصى لحجم الملف للمعالجة. |
| `AI_TOP_K_RESULTS` | `5` | عدد القطع التي أعيدت للبحث. |

راجع `Backoffice/config/config.py` للقسم الكامل عن الذكاء الاصطناعي/RAG وأي خيارات إضافية.

## كيفية استخدام المتجهات

- **بحث متجه:** يتم تضمين استعلام المستخدم مع نفس خدمة التضمين؛ يقوم التطبيق بإجراء بحث تشابه (مثل جيب تمام) في pgvector ويعيد الأجزاء العليا (top-k).
- **البحث الهجين:** يجمع بين تشابه المتجهات والبحث عن الكلمات المفتاحية لتحسين الاسترجاع.
- **RAG:** يتم تمرير الأجزاء المسترجعة كسياق إلى نموذج اللغة الكبيرة عند الإجابة على الأسئلة (مثل روبوت الدردشة، أسئلة وأجوبة مكتبة المستندات بالذكاء الاصطناعي، مستندات سير العمل).

صفحة مكتبة مستندات الذكاء الاصطناعي تتيح لك اختيار **ال فقط المتجه** أو **الهجين (الكلمات المفتاحية والتضمينات)** لميزة "اسأل".
