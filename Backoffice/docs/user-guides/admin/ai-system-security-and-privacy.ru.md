# Система ИИ: безопасность и конфиденциальность

В этом документе объясняется, как работает AI-ассистент в бэк-офисе, какие данные могут обрабатываться внешними провайдерами и какие технические меры применяются для снижения случайной утечки чувствительной информации.

## Масштаб

- **В области**: AI-чат (`/api/ai/v2/*`), AI Document Library / RAG, вопросы и ответы по workflow-doc, а также системы управления безопасностью вокруг них (DLP, очистка PII, аудитские события).
- **Вне сферы действия**: общая безопасность платформы (аутентификация, RBAC, резервные копии), за исключением случаев, когда это напрямую влияет на систему ИИ.

## Архитектура высокого уровня

- **Frontend**: чат-интерфейс (плавающий виджет + иммерсивный вид) в `app/static/js/chatbot.js`.
- **Backend**: Endpoints Flask API для AI-чата в `app/routes/ai.py` (HTTP + SSE) и `app/routes/ai_ws.py` (WebSocket).
- **Оркестрация**: `app/services/ai_chat_engine.py` управляет потоком чата (история, поиск, вызовы провайдера).
- **Провайдеры**: внешние LLM/эмбеддинги (например, OpenAI/Gemini/Azure OpenAI в зависимости от среды) плюс необязательные локальные компоненты.

## Какие данные могут быть отправлены внешним поставщикам

В зависимости от типа запроса и включенных функций, бэкенд может отправлять некоторую комбинацию:

- **Текст пользовательского сообщения**
- **История разговоров** (недавние сообщения, по мере необходимости для сохранения непрерывности)
- **Очищенный контекст страницы** (состояние/контекст интерфейса для помощи ассистенту; некоторые поля высокого риска удалены)
- **Полученные фрагменты документов/рабочих процессов** (для ответов RAG)

Важно: некоторые функции ИИ требуют внешних вызовов API (например, завершения чата, переписывания запросов, встраивания), поэтому **предотвращение отправки конфиденциальных данных** является основной целью безопасности.

## Основные меры контроля конфиденциальности/безопасности

### 1) Защита по предотвращению потери данных (DLP) при исходящих сообщениях

Перед тем как сообщение может быть отправлено внешнему провайдеру ИИ, бэкенд запускает лучшее сканирование DLP (на основе регулярных выражений) для выявления распространённых чувствительных шаблонов, таких как:

- электронные письма, номера телефонов
- JWT / жетоны предъявлятеля
- приватные ключи
- ключи паролей / секретов / API
- IBAN и номера платежных карт (с чеком Luhn для снижения ложных срабатываний)

**Пользовательский опыт**

- Если обнаружены чувствительные закономерности, ассистент может потребовать **пользовательского подтверждения** («Отправить всё равно») или **блокировать** сообщение в зависимости от конфигурации.
- Интерфейс объясняет риски и поощряет удаление чувствительного текста.

**Реализация**

- Логика DLP: `app/services/ai_dlp.py` (`analyze_text`, `evaluate_ai_message`)
- DLP применяется последовательно между транспортами:
  - HTTP JSON чат
  - SSE стриминг
  - WebSocket стриминг

**Конфигурация**

DLP настраивается напрямую в коде (не в переменных среды):

- `Backoffice/config/config.py`
  - `AI_DLP_ENABLED`
  - `AI_DLP_MODE` (типичные значения: `warn`, `confirm`, `block`)
  - `AI_DLP_MAX_SCAN_CHARS`

### 2) Чистка / редактирование PII перед внешними звонками

В дополнение к DLP (который может остановить запрос), система также применяет **PII очистку** (редактирование), чтобы снизить экспозицию, когда контент должен отправляться извне (например, чтобы помочь модели отвечать).

Скрабинг применяется к:

- текст пользовательского сообщения
- Фрагменты истории разговоров
- контекст страницы (рекурсивно)
- некоторые входы и логи для переписывания запросов

Реализация:

- `app/services/ai/providers/formatting.py`: `scrub_pii_text`, `scrub_pii_context`
- `app/services/ai_chat_engine.py`: применяет очистку перед вызовами провайдера

### 3) Минимизация контекста страницы

Фронтенд может отправлять контекст страницы для ответов на вопросы, связанные с интерфейсом. Бэкенд очищает и очищает эти данные, а также намеренно удаляет поля с высоким риском (например, URL-адреса или крупные сырые каплы), чтобы уменьшить случайные утечки.

Реализация:

- `app/utils/ai_utils.py`: общие помощники, такие как очистка контекста
- `app/services/ai/providers/formatting.py`: рекурсивная контекстная очистка

### 4) Логирование аудита событий DLP (без сохранения содержимого сообщения)

Когда DLP обнаруживает чувствительные паттерны, бэкенд записывает **событие аудита безопасности**, чтобы администраторы могли отслеживать, как часто срабатывает охрана и реагировать на рискованное поведение.

Свойства безопасности:

- Событие аудита **не хранит сообщение пользователя**.
- Он хранит только **счета и виды** находок (например, `{"kind":"jwt","count":1}`), а также метаданные, такие как транспорт, конечная точка и идентификаторы.

Реализация:

- `app/services/ai_dlp.py`: `log_dlp_audit_event`
- Модель: `app/models/system.py` (`SecurityEvent`, `context_data` JSON)
- Административный интерфейс:
  - Панель безопасности: `/admin/security/dashboard`
  - Список событий безопасности: `/admin/security/events`

Чтобы отфильтровать события с ИИ DLP, ищите следующие:

- `event_type = "ai_dlp_sensitive_detected"`

### 5) Аутентификация и контроль доступа

- Конечные точки ИИ защищены теми же механизмами аутентификации бэк-офиса (вход на основе сессии и потоки токенов Bearer, где это применимо).
- Страницы только для администратора (панель безопасности/события) требуют соответствующих разрешений (см. `app/routes/admin/security_dashboard.py`).

## Оперативное руководство (администраторы)

### Рекомендуемая политика

- Считать ИИ-ассистента **недоверенным для конфиденциальных данных**.
- Поощрять пользователей:
  - избегать отправки учетных данных, токенов, приватных ключей и персональных данных
  - заменить реальные идентификаторы на заполняющие при обращении за помощью (например, "<TOKEN>", <EMAIL>"")

### Как справляться с всплеском или инцидентом DLP

1. Проанализировать недавние события безопасности в разделе `/admin/security/events` и отфильтровать по `ai_dlp_sensitive_detected`.
2. Проверьте метаданные в `context_data` на наличие закономерностей (транспорт, клиент, частота, затронутые аккаунты).
3. Рассмотрите возможность временного ужесточения режима DLP до `block` в `Backoffice/config/config.py` и повторного развертывания при необходимости.
4. Если секреты могли быть раскрыты, поменяйте учетные данные (ключи API, токены) и проверьте журналы доступа.

## Ограничения и ожидания

- DLP — это **лучшее усилие** и основано на паттернах; Он может пропускать чувствительный контент и также давать ложные срабатывания.
- Чистка по PII также является лучшей работой; Это снижает риск, но не гарантирует полного удаления.
- Выводы ИИ могут быть некорректными; пользователям следует проверять важную информацию (интерфейс предупреждает об этом).
